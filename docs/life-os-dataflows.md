# Life OS dataflows

These diagrams explain the existing app and connected workflows. Arrows do not install a trigger or grant access. Notion remains the task store. Saved app data, fresh source reads and verified source changes are separate steps.

## Overall

```mermaid
flowchart LR
    N[Existing Notion tracker and original cards] --> P[Existing connected Life Sweep]
    K[Saved daily Knowledge Library lesson] --> P
    G[Gmail and primary personal Calendar] --> P
    P -->|Verified source families| D[(Private app database)]
    D --> A[Today · Tasks · Waiting · What’s On]
    A -->|Explicit task choice or request| Q[(Durable decision and request queue)]
    Q --> P
    P -->|Bounded source write and receipt| N
    C[Explicit agenda request] --> W[Existing request-only agenda workflow]
    N --> W
    G --> W
    W -->|Complete bounded agenda| D
    R[Owning AI review cards and Suggested Fixes] --> I[Separate Performance Review inbox]
```

Life Sweep retains its 08:00, 13:00 and 19:00 Europe/London schedule. Browser polling reads saved app data every minute while visible. A source request waits for an available connected publisher; it is not a new background scheduler. A failed source retains its previous dated family.

## Today

```mermaid
flowchart LR
    T[Complete tracker inventory] --> V[Identity and revision validation]
    L[Existing lesson for the London date] --> V
    S[Verified sweep summary and source times] --> V
    V --> D[(Independent tracker · learning · sweep families)]
    D --> B[Date · next actions · coming dates · waiting]
    D --> E[Expanded saved lesson and original link]
    B --> R[Refresh view: reread saved data]
    B --> Q[Refresh source: queue bounded tracker request]
    Q --> P[Existing publisher]
    P --> V
```

The lesson is reused, not regenerated by browser refresh. A source-read time is not a judgment date or evidence of phone delivery.

## Tasks and decision round trip

```mermaid
flowchart TD
    N[Original Notion card and complete tracker inventory] --> P[Publish new or changed full cards]
    P --> D[(Saved task projection)]
    D --> U[Search · filters · original source and history]
    U --> C[Explicit Done · Not doing · Pause · Resume]
    C --> Q[(Authenticated choice with task ID and source revision)]
    Q --> F[Existing publisher fetches current Notion card]
    F --> V{Current revision and choice valid?}
    V -->|No| X[Retain choice as stale or conflicting; no source overwrite]
    V -->|Yes| W[Checkpoint bounded update and unique receipt]
    W --> N
    N --> B[Fresh source readback]
    B --> R{Properties and receipt verified?}
    R -->|Yes| A[Acknowledge once and update saved projection]
    R -->|No| H[Retain pending work; reconcile missing step only]
    A --> D
```

Reasons, original deadlines and return dates are separate. An archived record is not reopened by an expired test date. A task action never approves a suggested fix, sends mail or changes Calendar.

## Waiting

```mermaid
flowchart LR
    G[Latest relevant conversation evidence] --> S[Normal existing Life Sweep scan]
    S --> N[Original tracker: Type · Status · context · links]
    N --> P[Complete verified tracker projection]
    P --> D[(Shared saved tasks)]
    D --> F[Waiting filter]
    F --> W[Who has the next move · priority · source context]
    W --> T[Shared original task detail and decision path]
```

The Waiting tab reuses the same records. Opening it neither scans Gmail nor creates follow-up tasks.

## What’s On

```mermaid
flowchart TD
    U[Explicit requested London date range] --> Q[(Saved agenda request)]
    Q --> W[Existing request-only agenda workflow]
    W --> C[Primary Calendar: exact bounds and every result page]
    W --> T[Complete tracker: active dated commitments]
    C --> V{Both reads complete?}
    T --> V
    V -->|No| E[Retain previous dated agenda and record ingestion error]
    V -->|Yes| M[Merge by Calendar Event ID; retain distinct overlaps]
    M --> O[Order events · travel · provisional items; separate overdue]
    O --> D[(Saved agenda with exact range and source times)]
    D --> R[Read back matching request and range]
    R --> A[Complete request receipt]
    D --> B[What’s On browser view]
```

A generated agenda is a read-only projection. It makes no Calendar, RSVP, task-status, reminder or email changes. Similar titles do not prove duplication.
