A quick first look

Load an example, then open its case

At the top of Bounceback, choose a Worked example and click Load example. Start with Routine recovery, then compare an unresolved exception, reuse of a checked fix, stale evidence, missing confirmation, wrong-account evidence or a reopened case.

  1. Get a follow-along output

    The loader prepares the case state and evidence for you. It uses the same recovery checks as the interactive story.

  2. Open the workspace

    Select a case in the queue to open its workspace in a pop-up. Source evidence, checks, guidance and the knowledge index open in their own detail cards.

  3. Stay in the app

    Close a card, or press Escape, to return to the previous view. Directory workflow cards also open a preview. Open full page is available when you want a separate tab.

Start with a routine problem

Choose REC-101 to see a known login problem move through the workflow.

  1. Choose the first case

    Select REC-101 in the case queue. Read the customer’s message and the task they need to get back to.

  2. Run the workflow

    Click Run workflow. Bounceback uses the approved session guidance, then checks that the customer can sign in, reach the right workspace and continue their work.

  3. Open the evidence

    Open source evidence to inspect the fictional account diagnostics. After running, open the recovery checks to see why the case can be marked Back to work.

Follow an exception through to recovery

Choose REC-102 and run it. There is no approved fix for this workspace problem yet.

  1. Keep the case open

    Needs investigation means the workflow has not confirmed recovery. It keeps the customer’s problem, evidence and steps already checked in the same case.

  2. Inspect before acting

    Open source evidence. Sign-in succeeds, but the customer cannot reach the team workspace. A successful login alone does not resolve the problem.

  3. Apply the prepared technical fix

    Click Apply prepared technical fix to simulate the result of a technical investigation. Once the recovery checks pass, Bounceback captures and indexes the checked fix automatically.

See the next case reuse the fix

After resolving REC-102, click Try next case, then run REC-103.

  1. Trace the reused guidance

    Open guidance · REC-102 shows the fix and its source. The new response reuses the checked solution without another technical investigation.

  2. Check this customer’s recovery

    Open 7 / 7 checks passed. A previous fix is useful evidence, but this case still needs matching account logs, the right workspace, a completed task and customer confirmation.

  3. Inspect the learning loop

    Open knowledge index to see the source case and version. Learning also shows that the existing record was reused, without creating a duplicate. Try Customer still blocked to reopen the case and withdraw the affected learned guidance.

Inspect the result

Understand the checks and AI plan

Click Inspect evaluation & AI in the case workspace. Three views explain the result:

  1. Source checks

    Inspect each recovery check and the evidence behind it. Passing checks describes this prepared case; it does not establish real-world model accuracy.

  2. Compare evidence

    Compare two prepared versions of the same fictional case, with and without customer confirmation. See why a technical fix alone can leave recovery unconfirmed.

  3. AI & model planning

    See which steps use ordinary code and where an LLM could help. Model and token-budget choices are a plan: they do not generate a new response. Recorded model examples belong to other workflows and are labelled separately.

Want to explore further? Case progress shows the decision trail. Learning shows the checked guidance. Evaluation & AI explains the prepared evidence and model plan. Model route & cost compares illustrative model and token-budget choices; changing the route does not change the prepared response.
